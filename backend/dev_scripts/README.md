One-off scripts from debugging the RAG embedding-dimension mismatch (768 vs 3072) and
chunk retrieval quality. Not part of the app; kept for reference.

Run from `backend/` with `python -m dev_scripts.<name>` (they import `app.*`, which
needs the backend root on `sys.path`, not the `dev_scripts/` dir).

- `test_len.py`, `test_len2.py`, `test_embed.py`, `test_genai.py`, `test_langchain_dim.py` —
  redundant checks of embedding output dimensions across model names. Safe to delete;
  kept only one would be needed going forward.
- `test_truncate.py` — checks cosine similarity after manually truncating a 3072-dim
  embedding to 768. Superseded by `embedding_service.py` doing this natively.
- `test_search.py` — ad-hoc retrieval diagnostic (query vs. stored chunks, finds a chunk
  by substring). Useful for future retrieval debugging.
- `dump_chunks.py` — prints the first 10 chunks in the DB.
- `reembed.py` — regenerates embeddings for all chunks in the DB in place.
- `test_step2.py`, `test_step3.py`, `test_step4.py` — httpx-based integration tests
  against a running `localhost:8000` server (upload, vector search, RAG chat). These are
  real tests, not scratch scripts; consider moving them into a proper `tests/` suite with
  pytest if the app grows.
- `test_files*/` — sample files generated by the step2/3/4 scripts; regenerated on each run.
